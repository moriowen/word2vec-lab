This experiment compares five routes to a Word2Vec model: two trained with gensim on movie reviews, a frozen pretrained model, a fine-tuned version of those pretrained weights, and a skip-gram implementation written from scratch. The same pipeline measures sentiment accuracy, lexical structure, and runtime cost.

Deliverable 1

How the two architectures work

A Word2Vec model comes down to two matrices and a dot product. It has no hidden layer or nonlinearity. W_in stores one row per word and becomes the final embedding table. W_out is used for the training objective, then discarded.

A and E use skip-gram with negative sampling. A centre word predicts each surrounding word independently. Each observed pair is scored against 10 negative samples from the unigram distribution raised to 0.75, avoiding a softmax over all 14,309 words.

B uses CBOW with hierarchical softmax. The context rows are averaged into one vector, which predicts the centre word. A binary tree over the vocabulary reduces one prediction from V decisions to log2(V).

The encoder, code, and decoder analogy only goes so far. The terms come from autoencoders, which reconstruct their own input. Word2Vec predicts a neighbouring word and throws away its output matrix after training. In the mapping above, the one-hot word is the input, W_in is the encoder, its 300-dimensional row is the code, W_out is the decoder, and the predicted context word is the output.

  1. Build the vocabulary from our corpus first intersect_word2vec_format only overwrites rows that already exist. It does not import Google's three million words, so D keeps the vocabulary built from SST.
  2. Set vectors_lockf to ones explicitly gensim 4.x does not create it. Without it the import either fails or silently freezes every row, leaving the imported vectors unchanged.
  3. Keep the learning rate low: alpha 0.005, 8 epochs Google never published their output matrix, so W_out starts random. Early updates must learn a new decoder as well as adjust the imported vectors. A standard learning rate distorts those vectors during the first epoch.
  4. Measure drift rather than assuming it Cosine between each word's warm-start vector and its final vector. The mean is 0.9609 and the median is 0.9731, confirming that the low learning rate preserved most of the pretrained structure.
Model E, beyond the requirement

Writing skip-gram with negative sampling

The handout suggests a brief look at the implementation. I chose to write it instead because that makes each part of Word2Vec concrete. src/sgns.py implements the vocabulary and counts, subsampling of frequent words, the unigram^0.75 noise table, a dynamic window, the two embedding matrices, and linear learning-rate decay. to_keyedvectors wraps W_in in a gensim object, which lets E use the same evaluation code as every other model.

The first version did not learn. Its loss stayed at exactly 1.3863 for all ten epochs, and accuracy was 0.4992, or chance on a balanced split. A loss of 1.3863 is 2·ln 2, what we get when every logit is zero. The problem was the loss reduction, not the sampler. Calling BCEWithLogitsLoss once on the positives and once on the negatives averages over B entries and over B·k entries, so at a batch of 8,192 the effective per-pair learning rate was about 3e-6. The measured gradient norm on W_in was exactly 0.0. I fixed it by writing Mikolov's equation 4 directly, summing across the k negatives, and averaging only across the batch.

Two component checks made the failure quick to locate. Subsampling retains 17.6% of occurrences of the. The noise table maps the from a raw frequency of 4.30% down to a sampled 1.31% while lifting execrable from effectively zero to 2e-5. Both results match the expected effect of the 0.75 exponent.

Brute-force query time grows with vocabulary size. C has 35 times as many words as the SST models and is 37 times slower at p50. An approximate index adds little value at 14,309 words. At 500,000, a query already takes 15 ms, and the full three-million-word Google model would take roughly 90 ms.

The 2 · V · d · 4 prediction holds within 3% for A, D and E. B comes in at 1.40 because hierarchical softmax also keeps Huffman-tree code and point arrays that the formula omits.

C's memory result does not match the prediction. 500,000 by 300 float32 is 600 MB and the measured increase is only 195.6 MB. macOS memory compression is a possible explanation because it can compress inactive anonymous pages, causing ru_maxrss to fall below the allocation. A Linux run should land near 600 MB if that explanation is correct. Until then, the gap remains unresolved.

A separate benchmark determined how E trains. On this vocabulary, MPS is slower than CPU (64.3 against 44.6 ms per batch) and sparse gradients are slower than dense gradients (52.6 against 44.6). The model is small enough for GPU launch and data transfer overhead to dominate. Sparse updates also offer little benefit. A batch of 8,192 pairs with 10 negatives touches roughly 90,000 index slots across 14,309 rows, so almost every row updates on each step. The planned text8 run will test whether both results reverse on a larger corpus.

Deliverable 6

Installation, running and measurement

Four setup and measurement problems took most of the debugging time. In each case, the visible error pointed away from the actual cause. The symptoms and fixes are recorded here as part of the requested implementation experience.

  1. gensim has no wheels for Python 3.14 The machine's default interpreter is 3.14. Installing gensim there starts a Cython source build and fails late in the process. The virtual environment therefore uses Homebrew Python 3.11.
  2. import gensim fails on a fresh unpinned install gensim 4.3.x imports scipy.linalg.triu, which scipy 1.13 removed. The ImportError points at gensim even though the incompatible scipy version is the cause. requirements.txt pins scipy<1.13 and numpy<2.
  3. The SST-2 split with hidden labels The GLUE copy sets every test label to -1. An accuracy calculation against those placeholders can still produce a plausible number. src/data.py prevents that by requiring two classes in the test labels.
  4. Whole-process peak RSS is not a model measurement The first memory table compared process peak RSS against the matrix prediction and returned 297.8 MB for a model with 34.3 MB of matrices. Process peak RSS also includes the interpreter, gensim, numpy, torch, and the resident corpus. src/measure_mem.py now measures an RSS delta in an isolated subprocess per model.

After pip install -r requirements.txt, four commands reproduce the main page. python -m src.main trains A and B and loads C. python -m src.run_eval adds similarity, latency, and error measurements. python -m src.measure_mem fills the memory table, and python -m src.build_report rebuilds both report variants. Model E is trained separately with python -m src.run_e and takes 160 seconds on CPU.
